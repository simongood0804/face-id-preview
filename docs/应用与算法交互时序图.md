# 应用与算法交互时序图

> 本文档描述**当前代码库的实际实现**（`:app` 上层应用 ↔ `:algo` 算法层 ↔ face-sdk AAR ↔ EVS 相机）的模块间交互时序，
> 每张图均标注**线程切换**。配套阅读：`docs/设计方案.md`（§5 帧处理、§16 模块化、§19.5 时序模块共享化）。
>
> **图例**：本文档全部使用 **ASCII 泳道时序图**，纯文本即可阅读，不依赖 Mermaid 插件。
> - 纵向为**时间轴**（自上而下推进），每步前的 `① ② ③` 为序号；
> - 横向每列为一个**参与模块**，列头 `[线程名]` 标注该模块代码执行所在线程；
> - `────▶` 同步调用（阻塞等待返回）；`- - ▶` 异步/回调（不等待）；
> - `◀────` 返回值；`★` 标注**线程切换点**；`║` 泳道分隔线；
> - 同一横向行内的多个动作发生在**同一线程**。

## 0. 分层与线程总览

### 0.1 分层结构

```
┌──────────────────────── :app 层 ────────────────────────┐
│  UI（Activity）  │ 渲染桥 │ 信号层 │ 帧会话 │ 相机      │
│  RecognitionActivity / FatigueActivity / DistractionActivity / │
│  BehaviorMonitorActivity / FusionMonitorActivity               │
└────────────────────────────────────────────────────────┘
                          ↓ 依赖
┌──────────────────────── :algo 层 ───────────────────────┐
│  AlgoSession（单例）→ FaceIDAlgorithmImpl → face-sdk AAR │
│  FrameProcessor / FrameDistributor / 时序状态机（纯逻辑） │
└────────────────────────────────────────────────────────┘
                          ↓ JNI / AAR
┌──────────────────── EVS / face-sdk native ──────────────┐
└────────────────────────────────────────────────────────┘
```

跨层只通过 3 个门面交互：`AlgoSession`（算法会话）、`FrameSession`（相机帧会话）、`FaceOverlayBridge` + `SignalDispatcher`（应用侧消费）。

### 0.2 线程清单

| 线程 | 创建位置 | 职责 | 关键约束 |
|------|---------|------|---------|
| **主线程（UI）** | Android 框架 | Activity 生命周期、View 绘制、`FaceOverlayBridge` 操作 | `FaceOverlayBridge` **必须**在 UI 线程调用 |
| **HAL 回调线程** | EVS / `EvsHalWrapperImpl` | `onFrameEvent` 收帧；直接触发 `onFrameData` → 算法提交 | **不允许阻塞**，否则丢帧 |
| **GL 线程（GLThread）** | `GLSurfaceView` | `EvsGL20CameraRenderer.onDrawFrame` → `getNewFrame()` 渲染 | 与算法路径独立并行 |
| **DISPATCH 线程** | `FaceIDCameraController.dExecutor`<br/>（`EvsExecutorService("DISPATCH")`） | 相机开/停/释放、断线重连 | 单线程串行 |
| **AlgoProcessor 线程** | `AlgoSession.mAlgoExecutor`<br/>（单线程，`NORM_PRIORITY - 2` = 3） | UYVY→RGB 转换、`processFrame` 推理、**时序状态机、结果回调** | 单线程串行；低优先级避免抢占 GL |
| **Dump 线程池** | `FaceIDAlgorithmImpl.mDumpExecutor` / `mContinuousExecutor` | 原始帧落盘、连续 dump 采样 | 与推理线程解耦 |
| **Car 回调线程** | `CarPropertyManager` | 车速 / 门锁属性上报 | UI 更新需自行切主线程 |
| **主线程 Handler** | `FaceIDAlgorithmImpl.mMainHandler` | dump 完成回调 | — |

> **核心约定**：算法结果回调（`setResultCallback`）发生在 **AlgoProcessor 线程**，所有 UI 更新必须 `runOnUiThread`。

**关键点**

| # | 要点 |
|---|------|
| ③–⑦ | 全在主线程**同步阻塞**（`FaceSDK.init` + 标定加载，一次数百 ms） |

### 线程切换说明（初始化）

| 阶段 | 线程 | 切换说明 |
|------|------|---------|

| `configureSurface` | 主线程 | 仅注册回调 |
| `open()` | 主线程 → **DISPATCH 线程** | `startCamera` 内 `dExecutor.submit { handleStartVideoStream }` |
| 首帧尺寸回调 `onFrameSizeChanged` | **GL 线程**（`getNewFrame` 内触发）→ `surface.post` → 主线程 | `FrameSession.fitFixedAspect` 在 `post` 内执行 |

### 线程切换说明（单帧链路）

| 步骤 | 线程 | 备注 |
|------|------|------|
| `onFrameEvent` → `onFrameData` → `readFrame` → `submitFrame` | **HAL 回调线程** | 全同步，**不可阻塞** |
| `processLoop`（转换 + 推理 + 时序） | **AlgoProcessor 线程** | 单线程串行；低优先级（=3）避免抢 GL |
| `mResultCallback` | 仍 **AlgoProcessor** | 页面内 `runOnUiThread { }` 才切主线程 |
| `setFaces` / TextView | **主线程** | 操作 View 必须在主线程 |
| 渲染路径 `getNewFrame` | **GL 线程** | 与上述链路**完全独立**，见 §3 |

## 3. 帧的两条独立访问路径（算法 vs 渲染）

两条路径**并行独立**，不互相阻塞；交汇点只有 `FaceIDCameraController.buffers`（2 槽 + `bufferLock`）。

```text
 [HAL回调线程]         [GLThread]           [AlgoProcessor线程]
  CameraController      （渲染）              FrameProcessor
  FrameDistributor                           FaceIDAlgorithmImpl
      │                     │                        │
═══ 路径 A：算法（HAL 回调线程「推」，不经过 GL 线程）═══════════════════════════
      │                     │                        │
 ①● onFrameEvent(i, buffer) │                        │
 ②● onFrameData → onFrame() │                        │
 ③● readFrame + submitFrame │                        │
      ├─────────────────────┼───────────────────────▶│
      │  ★ 切到 AlgoProcessor（HAL 回调线程本帧任务结束）│
 ④● 转换 + 推理 + 时序判定   │                        │
      │  └─ 路径 A 结束 ──────┼────────────────────────┘
      │                     │                        │
═══ 路径 B：渲染（GL 线程「拉」，不经过 FrameDistributor）═══════════════════════
      │                     │                        │
      │               ⑤● getNewFrame() 每帧轮询      │
      │◀────────────────────┤                        │
 ⑥● bufferLock 内 dequeue 遍历│                       │
 ⑦● 返回 EvsBufferDesc      │                        │
      ├────────────────────▶│                        │
      │               ⑧● EvsGL20CameraRenderer 绘制  │
      │  └─ 路径 B 结束 ──────┘                        │
      │                     │                        │
──────┴─────────────────────┴────────────────────────┴───▶ 时间

┌─ 共享资源（两路唯一交汇点）──────────────────────────────────────────────────┐
│  FaceIDCameraController.buffers（MAX_RECEIVE_FRAME = 2 槽）+ bufferLock       │
│  三方并发访问，统一加锁：                                                     │
│    · HAL 回调线程  → queue 入队                                              │
│    · GL 线程       → dequeue 出队                                            │
│    · DISPATCH 线程 → recovery 回收                                           │
└──────────────────────────────────────────────────────────────────────────────┘

┌─ 首帧尺寸变化特殊处理（在 getNewFrame 内，GL 线程）───────────────────────────┐
│  ① 检测 desc 尺寸 ≠ 缓存尺寸                                                 │
│  ② 触发 onFrameSizeChanged 回调（链式：FrameSession 适配 + 上层逻辑）         │
│  ③ 立即 recycle 该帧并 break（丢弃，不渲染）                                 │
│  ④ 等 surface.post 完成重建 → 下一帧再正常渲染（防拉伸闪屏）                 │
└──────────────────────────────────────────────────────────────────────────────┘
```

### 线程切换说明（双路径）

| 路径 | 触发方式 | 线程 | 互扰关系 |
|------|---------|------|---------|
| 算法 | HAL 回调**推** | HAL 回调线程 → AlgoProcessor | 不经过 GL 线程，渲染卡顿不影响推理提交 |
| 渲染 | GL 线程**拉**（`getNewFrame`） | GLThread | 不经过 FrameDistributor |
| 共享资源 | `buffers`（2 槽）+ `bufferLock` | — | HAL 回调线程 queue / GL 线程 dequeue / DISPATCH 线程 recovery 三方并发，统一加锁 |
| 尺寸回调 | `onFrameSizeChanged` | **GL 线程**（`getNewFrame` 内）→ `surface.post` → 主线程 | 链式保留：FrameSession 适配 + 上层逻辑 |

### 8.3 三条时序链路的线程对照

| 链路 | 时序逻辑执行线程 | 消费（UI）线程 | 备注 |
|------|----------------|--------------|------|
| 行为（`BehaviorStateMachine`） | **AlgoProcessor** | 主线程 | 与算法同线程，串行无锁 |
| 疲劳（`FatigueStateMachine`） | **AlgoProcessor** | 主线程 | 同上；门开复位走 Car 回调线程（带锁） |
| 分心（`DistractionStateMachine`） | **主线程** | 主线程 | 在 `setResultCallback` 的 `runOnUiThread` 之后 |

### 线程切换说明（生命周期）

| 步骤 | 线程 | 备注 |
|------|------|------|
| `acquire` / `release` | 主线程 | 加锁 + 原子计数 |
| `open()` / `stop()` | 主线程 → **DISPATCH** | `dExecutor.submit` 异步执行 |
| `attach` / `detach` | 主线程 | 直接赋帧源回调字段 |
| `doRelease`（算法侧） | 主线程 | 仅清 `mResultCallback` |

## 10. 反向控制接口汇总（应用 → 算法）

| 接口 | 调用方 | 调用线程 | 说明 |
|------|--------|---------|------|
| `initialize(context, config)` | `AlgoSession` | 主线程 | 一次；内部同步加载模型 |
| `setFlagAndReset(flag)` | `AlgoSession.acquire` | 主线程 | 切模块裁剪模型 + 复位眼嘴校准 |

| `setCropOffset(x, y)` | `FrameProcessor` | AlgoProcessor | 恒为 0 |

## 附：已知不对称点（供后续评估）

1. **时序模块线程不统一**：行为/疲劳在 AlgoProcessor，分心在主线程。若后续需要统一，可把分心判定也下沉到 `AlgoSession`（但其输入依赖 `HeadRayZoneDetector`，且 `SignalDispatcher` 属 `:app` 层）。
2. **`setVehicleSpeed` 走单线程算法队列**：虽为轻量调用，仍排在推理任务之后，极端情况下车速档位更新有延迟。
3. **flag 裁剪与共享状态机的交互**：不带 `FaceFlag.BEHAVIOR` 的页面（识别/疲劳/分心），其帧仍会喂入共享行为状态机（`behaviorClass` 默认 0 = normal），相当于给"已确认行为"续命。
4. **渲染路径与算法路径各自访问同一帧**：`buffers` 仅 2 槽，高负载时可能加剧 HAL 丢帧。
