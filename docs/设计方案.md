## 1. 项目概述

基于 **Android 10**（`minSdk 29` / `targetSdk 29` / `compileSdk 31`），系统应用（`android.uid.system` 共享 UID），利用 **EvsSDK**（`com.android.car:evs:1.0.7`）控制 DMS 摄像头，实现驾驶员监控（DMS）人脸识别与预览。

### 1.1 双进程架构（v3.0 核心）

项目以**两个进程**运行，职责彻底分离，唯一关联为**共享内存（`ShmQueue`）分享算法结果**：

```
┌──────────────────────────────────┐      Binder(注册/订阅/取数)      ┌──────────────────────────────────┐
│    渲染进程（主进程, 默认进程）     │ ◄──────────────────────────────  │     算法进程（:algo）             │
│  ui/PreviewActivity               │       SharedMemory(算法结果)     │  shmtest/AlgoEngineService       │
│  · 帧数据渲染 (EvsGL20CameraRenderer)│  ◄──────────────────────────  │  · 独立取帧 (FaceIDCameraController)│
│  · 算法结果处理/绘制 (FaceOverlayView)│                                │  · 算法分析 (FaceIDAlgorithmImpl)  │
│  · dump 图像处理 (DumpManager)     │                                │  · 信号整合 (Distraction+Vehicle) │
└──────────────────────────────────┘      AlgoEngineBridge            │  · 结果按模块发布 (CapabilityPublisher)│
                                                                      └──────────────────────────────────┘
```

**职责划分**：
- **算法进程（`:algo`，`AlgoEngineService`）**：独立取帧 → 算法推理 → 整合车速/分心 → 按能力模块 topic 发布到共享内存。完全自包含。
- **渲染进程（主进程，`PreviewActivity`）**：帧数据渲染、算法结果消费绘制、dump 图像处理。作为「内建订阅者」通过 `register → subscribe → topic 过滤消费` 获取渲染所需模块。

**关联**：
- **共享内存**：算法结果（人脸/头姿/视线/分心/车速）通过 `ShmQueue` 分享。
- **Binder**：`AlgoEngineBridge`（引擎控制 + 能力注册/订阅 + dump 路径下发）。

### 1.2 核心流程

```
EVS 相机取流 → (渲染进程) 帧渲染 / (算法进程) 帧推理
             → 算法进程整合信号 → 按模块发布到共享内存
             → (渲染进程) 订阅消费 → Overlay 绘制 → 预览显示
```

### 1.3 核心约定

- **算法类型**：自研算法，通过 AAR 集成（`face-sdk-v1.1.4.aar`），算法团队实现 `IFaceIDAlgorithm` 接口。
- **算法输入**：RGB888 帧数据（900×900 裁剪后）+ 宽高。
- **算法输出**：`FaceIDResult`（人脸框、关键点、地标、头姿、视线、分心、DMS 分区等）。
- **关键要求**：分层解耦、故障隔离——某一层故障不影响其他层；避免因未及时归还 Buffer 导致阻塞。

## 3. 双进程共享内存总线（bus/ShmQueue）

### 3.1 设计定位

FACEP-010 用 Android `SharedMemory` 实现**跨进程无锁环形缓冲**（替代早期 JVM 内存 `BusQueue`），是算法进程与渲染进程唯一的帧数据关联通道。

### 3.2 核心结构

```kotlin
class ShmQueue private constructor(
    private val buffer: ByteBuffer,
    private val capacity: Int,
    private val maxReaders: Int
) {
    // —— 发布（单写者：算法进程）——
    fun publish(topic: Int, payload: ByteArray): Long
    // —— 消费（多读者：渲染进程/外部模块）——
    fun registerReader(): Int            // 找第一个空闲槽，复用注销空洞（FACEP-011 P2）
    fun unregisterReader(readerId: Int)  // 释放槽位，之后可复用
    fun hasNext(readerId: Int): Boolean
    fun readNext(readerId: Int): ShmMessage?  // ShmMessage(topic, payload, sequence)
    fun close()
    companion object {
        fun create(name, capacity, maxReaders): ShmQueue
        fun attach(shm: SharedMemory): ShmQueue
    }
}
```

**关键设计**：
- **无锁环形缓冲**：读写指针分离，写者不等待最慢读者，慢读者独立指针追赶。
- **消息带 topic**：`ShmMessage(topic, payload, sequence)`，消费端可按 topic 过滤，是「按模块订阅/发布」的基础。
- **槽位分配**（FACEP-011 修复）：`registerReader` **遍历找第一个空闲槽**（`readerValid==0`）复用注销产生的空洞，`initializeHeader` 槽位全置 0，进程内 `readerLock` 保证「找槽 + 置位」原子，避免注销后重注册落到已占用槽位导致 reader 冲突。
- **关闭安全**（FACEP-011 修复）：`publish` 检查 `closed`，close 后拒绝写入，防并发 stopEngine 写坏映射。

### 3.3 共享内存容量（当前配置）

`AlgoEngineService` 创建：`ShmQueue.create("algo_result", capacity=16, maxReaders=4)`，`slotPayloadSize=1024`。

- **总大小**：`totalSize(16,4) = 64 + 16×1028 ≈ 16.1 KB`。
- **槽位数**：`capacity=16`，即环形缓冲**最多同时容纳 16 条消息**（写者不等待最慢读者，会覆盖最旧数据）。
- **全量订阅（5 模块）**：每帧发布 5 条（FACE_DETECT/HEADPOSE/GAZE/DISTRACTION/VEHICLE_SPEED 各 1），16 槽位约容纳 **3.2 帧**。
- **单条消息上限**：`MAX_MESSAGE_BYTES=1024`。各模块单条均较小（≤81B），无超限风险。（注：早期曾考虑传输 106 密集地标，约 848B/条，因需精确索引且开销大，已决定不传。）
- **潜在风险**：若未来模块单条超过 1024B，`publish` 会因超限失败；全量注册如需容纳更多帧，可增大 `capacity`。

## 4. 算法能力服务化（shmtest，FACEP-011）

把 `:algo` 算法进程的能力做成**可被其他 App 模块依赖的服务**：外部模块通过接口文档注册 + 初始化即可使用，并支持**按模块订阅/发布**。

### 4.1 能力模块（CapabilityModule）

| 模块枚举 | topic id | 输出内容 | 内部依赖 |
|----------|----------|----------|----------|
| `FACE_DETECT` | 0x01 | 帧尺寸、人脸框、置信度、zoneId、5 关键点 | 无 |
| `HEADPOSE` | 0x02 | pitch / yaw / roll | FACE_DETECT |
| `GAZE` | 0x03 | valid / yaw / pitch / calibrated | FACE_DETECT |
| `DISTRACTION` | 0x04 | distracted、band(fast/slow)、thresholdMs、score/hpScore/gazeScore | FACE_DETECT + VEHICLE_SPEED |
| `VEHICLE_SPEED` | 0x05 | speedKmh（负数=无数据） | 无 |

### 4.2 能力接口（AlgoEngineBridge）

一个 Binder 同时承载引擎控制（渲染进程用，事务码 1-5）+ 能力注册/订阅（外部模块用，事务码 6-10）：

```kotlin
interface AlgoEngineBridge : IInterface {
    // 引擎控制（渲染进程）
    fun getSharedMemory(): SharedMemory
    fun getState(): String
    fun start(): Boolean
    fun stop()
    fun setDumpPath(path: String)
    // 能力注册/订阅（外部模块，FACEP-011）
    fun register(packageName: String, token: IBinder?): Int
    fun unregister(clientId: Int)
    fun init(modelDir: String): Int
    fun subscribe(clientId: Int, moduleIds: IntArray): Int
    fun unsubscribe(clientId: Int, moduleIds: IntArray): Int
}
```

**错误码**：`ERR_OK=0 / ERR_CLIENT_INVALID=-1 / ERR_CLIENT_FULL=-2 / ERR_INVALID_MODULE=-3 / ERR_NOT_INITIALIZED=-4 / ERR_ACCESS_DENIED=-5`；`MAX_CLIENTS=4`。

### 4.3 多消费者管理与安全（AlgoEngineService）

- **消费者注册表** `mClients`（clientId→包名）+ **订阅表** `mSubscriptions`（clientId→模块集合），`mClientLock` 保护。
- **uid 校验**：`register` 校验 `Binder.getCallingUid() == Process.myUid()`，仅放行同 `android.uid.system`；`Manifest` 的 `AlgoEngineService` 为 `exported=true`。
- **死亡清理（linkToDeath）**：`register(packageName, token)` 对客户端 token `linkToDeath`，客户端进程崩溃自动 `unregister`。
- **生命周期**：`stopEngine` 清空注册表/订阅表/死亡监听，防引擎重启后的「幽灵订阅」。

### 4.4 按模块发布（CapabilityPublisher）

```
AlgoEngineService.onAlgorithmResult (算法线程, 每帧)
  └─▶ CapabilityPublisher.publishModules(AlgorithmResult)
        ├─ subscribed = subscribedTopicsSnapshot()  // 有订阅者的模块集合
        ├─ FACE_DETECT.topic ∈ subscribed ? publish(0x01, FaceBoxData)
        ├─ HEADPOSE.topic  ∈ subscribed ? publish(0x02, HeadposeData)
        ├─ GAZE.topic      ∈ subscribed ? publish(0x03, GazeData)
        ├─ DISTRACTION     ∈ subscribed ? publish(0x04, DistractData)
        └─ VEHICLE_SPEED   ∈ subscribed ? publish(0x05, SpeedData)
```

**要点**：只发布有订阅者的模块（无订阅则整帧跳过），节省共享内存带宽。

### 4.5 客户端 SDK（FaceCapabilityClient）

供外部 App 模块接入，屏蔽 Binder/共享内存细节：

```kotlin
class FaceCapabilityClient(context) {
    fun connect(): Boolean            // 阻塞等待绑定完成（CountDownLatch，超时 2s）
    fun init(): Int                    // 注册 + 初始化 + 一次性 attach 共享内存
    fun subscribe(modules): Int
    fun unsubscribe(modules): Int
    fun obtainFaceBox(): FaceBoxData?  // 按模块取数（复用 init 附着的 reader）
    fun obtainHeadpose() / obtainGaze() / obtainDistract() / obtainSpeed()
    fun disconnect()
}
```

**设计要点**：
- `connect()` 用 `CountDownLatch` 等待 `onServiceConnected`（Binder 回调异步），避免时序竞态。
- `init()` 一次性 attach 共享内存 + `registerReader` 并缓存，`obtain*` 复用，避免反复 mmap + IPC + reader 槽位耗尽。
- 线程安全：状态字段 `@Volatile` + `mLock` 保护。

### 4.6 对外接口文档

`docs/FaceCapability_接入说明.md` 给出三步用法：
1. `connect()` 注册
2. `init()` 初始化
3. `subscribe([模块])` → `obtainXXX()` 按需取数

## 5. 算法进程内部（:algo）

### 5.1 帧处理（FrameProcessor）

`FrameProcessor` 从 `IFaceIDAlgorithm` 接口（解耦具体实现），单槽替换 + ROI 裁剪：

```kotlin
class FrameProcessor(
    mAlgorithm: IFaceIDAlgorithm,   // 接口解耦
    mExecutor: ExecutorService,
    mCallback: (FaceIDResult) -> Unit,
    onRawFrame: ((ByteArray, Int, Int) -> Unit)? = null  // 渲染层 dump 帧源（主进程传入）
)
```

**单槽替换 + ROI 裁剪**：
- 单槽替换（`mPending`），跳帧处理，避免堆积。
- 裁剪 900×900 ROI（UYVY → RGB888 一次转换），裁剪窗口跟随人脸。
- `setCropOffset()` 设置偏移，算法内坐标修正回原图空间。

### 5.2 算法接口（IFaceIDAlgorithm）

```kotlin
interface IFaceIDAlgorithm {
    class FaceIDResult(...)  // faceId/confidence/faceRect/keypoints/landmarks/headpose/gaze/zone
    fun initialize(context, config): Boolean
    fun processFrame(frameData, width, height, format): FaceIDResult
    fun setCropOffset(x, y)        // 默认空实现
    fun release()
}
```

### 5.3 信号整合（DistractionStateMachine + VehicleSignalSource）

- **`DistractionStateMachine`**：按「持续时间」判定分心（非帧数），车速分档防抖：
  - `TRIGGER_MS_FAST=1500ms`（≥50km/h 或无车速）、`TRIGGER_MS_SLOW=3000ms`（<50km/h）、`CLEAR_MS=500ms`。
- **`VehicleSignalSource`**：封装 Car VHAL 车速订阅（`PERF_VEHICLE_SPEED`，m/s→km/h×3.6）；`onSpeedChanged` 回调 `(Float, Boolean)`（km/h，是否有效）；连接失败/断开 → 车速置 -1（无效），不抛异常。

### 5.4 算法进程生命周期

```
onBind → bindCount++ → startEngine()（首次）
  · new FaceIDAlgorithmImpl().initialize()   // 加载模型（可耗时数秒）
  · new FrameProcessor(algorithm, executor)   // 算法线程池每次 start 重建
  · FaceIDCameraController + CameraManager 独立取帧
  · CapabilityPublisher 按订阅发布
onUnbind → bindCount-- → 若 0 → stopEngine()
  · 停止相机/算法/线程池，关闭队列
  · 清空注册表/订阅表/死亡监听
```

## 6. 渲染进程（ui/PreviewActivity）

### 6.1 职责

渲染进程只做三件事：**帧渲染、结果消费绘制、dump 处理**。

```
onCreate:
  initViews()
  mDumpManager = DumpManager(this)         // 渲染层 dump 控制器
  initRenderModules()                       // 相机取帧 + GL 渲染 + 绑定算法服务
  startPreview()
```

### 6.2 订阅消费链路（FACEP-011 方案 A）

```
onServiceConnected:
  register(packageName, token) → clientId
  init("")
  subscribe(clientId, [FACE_DETECT, DISTRACTION, VEHICLE_SPEED])  // 渲染所需模块
  getSharedMemory() → ShmQueue.attach → registerReader
  setDumpPath(dumpDir)
  startResultConsumer()

startResultConsumer (消费线程):
  while(q.hasNext(rid)):
    topic = m.topic
    when(topic):
      FACE_DETECT   → faceBox  = FaceBoxData.decode(payload)
      DISTRACTION   → distract = DistractData.decode(payload)
      VEHICLE_SPEED → speed    = SpeedData.decode(payload)
      HEADPOSE/GAZE → 忽略（渲染不订阅）
  // 该轮有新数据 → 组装不可变 ModulesSnapshot 快照 → runOnUiThread { handleModules() }

handleModules (UI 线程):
  读 mModules 快照 → setDistracted / updateSpeedText / setFaces（绘制）
```

**设计要点**：
- **快照原子化**：用不可变 `ModulesSnapshot(faceBox, distract, speed)`，消费线程组装后单一 `@Volatile` 引用原子替换，避免人脸框/分心/车速跨帧错位。
- **数据未变化跳过绘制**：该轮无新数据不触发 UI 刷新，减少无效绘制。
- **onDestroy 注销**：销毁时 `unregister`（幂等）+ 清理队列 + 断开服务。

### 6.3 dump 图像处理（DumpManager）

渲染层 dump 控制器，**与算法实例解耦**：

```kotlin
class DumpManager(context) {
    fun cacheFrame(uyvy, w, h)          // 渲染层每帧缓存（节流）
    fun isDumpAvailable(): Boolean      // 读系统属性 algorithm_face_dump_enable
    fun triggerManualDump(onResult)     // 保存最近帧为 PNG（后台线程）
    fun clearDump(onResult)             // 清空 debugDump + 删 sdcard 目录
    fun moveToSdcard(onResult)          // 移动 PNG 到 /sdcard/debugDmsDump
    fun getDumpDir(): File              // 供通过 Binder 下发给算法进程
    fun release()
}
```

**要点**：
- 帧画面 dump/clear/move 由渲染层负责，算法进程不参与。
- 算法处理后数据的 dump 路径由渲染层通过 Binder `setDumpPath` 下发给算法进程（`FaceIDAlgorithmImpl.setDumpPath` → `FaceSDK.setDebugDumpPath`）。
- 帧缓存用**不可变 `FrameCache` 数据类原子替换**，消除宽高不一致越界。

## 7. 完整数据流

### 7.1 跨进程帧数据流

```
EVS HAL
  ├─▶ [算法进程] FaceIDCameraController.onFrameData
  │     └─▶ FrameProcessor.submitFrame (单槽替换 + ROI 裁剪)
  │           └─▶ IFaceIDAlgorithm.processFrame → FaceIDResult
  │                 └─▶ 整合车速/分心 → CapabilityPublisher 按模块发布到 ShmQueue
  │
  └─▶ [渲染进程] FaceIDCameraController.onFrameData
        ├─▶ EvsGL20CameraRenderer.getNewFrame → GLSurfaceView 预览
        └─▶ cacheFrameForDump (节流缓存给 DumpManager)
```

### 7.2 跨进程结果流（按需订阅）

```
算法进程: AlgoEngineService.onAlgorithmResult
  └─▶ CapabilityPublisher → publish(topic, ModuleData)  只发有订阅者模块
        └─▶ ShmQueue（共享内存）
              └─▶ 渲染进程/外部模块: readNext(rid) 按 topic 过滤 → 反序列化对应模块
```

### 7.3 能力服务生命周期

```
外部模块: FaceCapabilityClient.connect() → init() → subscribe() → obtain*() → disconnect()
  │          │               │               │                │
  ▼          ▼               ▼               ▼                ▼
算法进程: bind → register(uid校验) → init → 订阅表 → 按模块发布 → unregister(或 linkToDeath 死亡清理)
```

## 8. 容错与故障隔离

| 机制 | 实现 | 效果 |
|------|------|------|
| **多进程隔离** | 算法/渲染分进程运行 | 单进程崩溃（如算法异常）不影响另一进程，靠 binder/共享内存解耦 |
| **多读者独立指针** | `ShmQueue` 每个 reader 独立读指针 | 慢读者不阻塞写者，不被其他读者拖垮 |
| **按需发布** | `CapabilityPublisher` 只发布有订阅者模块 | 无订阅者时整帧跳过，减少带宽与写压力 |
| **关闭安全** | `ShmQueue.publish` 检查 `closed` | 并发 stopEngine 不会写坏映射 |
| **槽位复用** | `registerReader` 找空闲槽 + 进程内锁 | 注销后重注册不冲突，多客户端安全 |
| **uid 校验** | `register` 校验调用方 uid | 仅同 `android.uid.system` 可接入，防滥用 |
| **死亡清理** | `linkToDeath` 监听客户端 | 客户端崩溃自动注销，防僵尸 clientId 占满槽位 |
| **回调异常隔离** | 各回调 try/catch | 单点异常不崩溃、不外传 |
| **数据快照原子** | `ModulesSnapshot` 不可变引用 | 渲染端避免跨帧数据错位 |

## 13. 已知问题与注意事项

### 13.1 已知限制

| 问题 | 说明 |
|------|------|
| **跨进程 readerCount 原子性** | `ShmQueue.registerReader` 进程内锁保证同进程原子；跨进程并发注册受 SharedMemory 无 CAS 限制，但注册是低频操作（连接时一次），冲突窗口极小 |
| **按需发布 + 订阅多模块的过期数据** | 客户端订阅 A+B，算法进程某帧只发布 A（B 无其他订阅者）→ `obtainB()` 返回旧值；属「按需发布」固有语义，文档已说明 |

### 13.2 注意事项

- **Kotlin/Java 互操作**：Kotlin 接口的默认实现方法（如 `setCropOffset`），Java 实现类仍需显式实现（`DefaultImpls` 对 Java 不可见）。
- **Kotlin 版本较老**：不支持 `enum.entries`（1.9+）和 `IntArray` 的 lambda 集合 API（`mapNotNull { it }`），代码需用 `values()` + 显式循环规避。
- **`Car.createCar(Context, ServiceConnection)` 已弃用**：功能正常，后续可迁移 lifecycle listener。
- **分心阈值是工程经验值**：非法规强制，已抽成常量可调。
- **dump 路径**：通过 Binder `setDumpPath` 下发，不写系统属性、不依赖算法实例。
